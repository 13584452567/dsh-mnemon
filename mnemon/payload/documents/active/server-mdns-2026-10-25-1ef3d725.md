## 触发与症状

用户日志中同一台手机（`192.168.1.144`）在设备列表里出现**两个端点**：

- `adb-tcp:192.168.1.144:43407` —— 宿主持久化记住的直连目标（`settings.json` 的 `pairedNetworkTargets`），**旧端口**；
- `192.168.1.144:36695` —— 本次扫码配对后 adb server 侧的目标，**新端口**。

属性查询与 logcat 都挂在旧的 43407 上，错误为 `ObjectDisposedException` 与 `Cannot write application data on closed/failed TLS connection`；失效端点被反复拨号，也是手机上反复弹出授权框的来源。实测该手机仍在线，但 43407 与 36695 两个端口随后都不再监听，确认**保存的端口确实已过期**。

根因不是 TLS 或配对协议，而是**端点身份未收敛**：宿主只在“新增”端点，从不把已记住的端口对齐到 server 的当前值，也不消除同主机的重复端点。

## 设计要点

### 有 adb server 的配对链路（对齐 `UotanToolboxNT` 的 `ADBPairHelper.ScanmDNS`；mDNS 实现不变）

用户要求参考 `UotanToolboxNT` 的做法（`adb pair ip:port 密码` 成功后重新执行 `adb mdns services`，再对 `_adb-tls-connect` 行执行 `adb connect`），本仓库据此调整 `AdbQrPairingService`：

1. `host:pair` 成功后**重读 `host:mdns:services`**，先 `host:connect:` 设备的 `_adb-tls-connect` 行；每 ≤2 秒重读到 20 秒期限，直到出现可用行（`TryConnectServerTableAsync`）。
2. 表内没有该行才回退到现有本地 mDNS 浏览（`AdbMdnsDiscovery` 保持不变）；**配对前收集的候选排到最后**——此前它排在最前，正是拿到旧端口的直接原因。
3. `host:connect:` 成功后用 `host:devices-l` **复核目标不是 `offline`**，避免把“能建 TCP 但不是 adbd”的端口当成连接成功。
4. 直连配对遇到 TCP 连接失败时**重新解析端点重试一次**（重复扫同一张码会让配对端口变化）。

### 宿主侧消除“旧端口 + 新端口”并存（`DeviceMonitorService`）

- **扫描时对齐已记住的目标**（`DeviceMonitorService.Discovery.cs`）：server 已列出同一主机时，把记住的端口改成 server 的当前端口，忽略 `offline` 行。
- **同主机去重**：已有可用的 ADB TCP 行（含 DNS-SD 实例名经别名解析出的 `ip:port`）时，不再单独生成 `adb-tcp:` 行，两个端口不会再同时出现；server 行离线时**不遮蔽**记住的端点。
- **新直连配对成功后删除同一主机的其它旧目标**；设备列表优先显示已通过 TLS 握手验证（`MarkManualNetworkTargetVerified`）的目标（`DeviceMonitorService.Pairing.cs` / `.Remote.cs`）。
- **mDNS 侧补 `LastSeenUtc`**：连接端口按“最近广播的实例”选择，地址匹配优先于仅主机名匹配，避免设备换端口后仍落在旧端口。

## 验证（Windows x64，.NET 10 Debug）

- `dotnet build UotanStudio.slnx --no-restore -c Debug`：0 警告 0 错误；Comm/Tests 单独构建同样 0 警告。
- 定向：`UotanStudio.Tests.Devices` 276/276、`UotanStudio.Tests.Protocols` 45/45（新增同主机去重、离线行、SRV 时间戳与候选排序用例）。
- 全量：7363 总数 / 7356 通过 / 7 跳过 / 0 失败；`dotnet format` whitespace 与 style 均零报告。
- NativeAOT：`dotnet publish UotanStudio.Desktop -c Release -r win-x64 -p:PublishAot=true` 成功，`UotanStudio.Desktop.exe` 154,809,344 B；仅有既有第三方 IL2026/IL2104/IL3053 警告（YamlDotNet、Common.Logging、LTRData.Extensions、Makaretu 的 Linux-only 辅助方法）。
- 环境坑：正在运行的 `UotanStudio.Desktop` 会锁住 `bin/Debug`，改动生效前必须先关闭该应用再重建。

## 未验证边界

- 真机扫码端到端仍未验证（本机没有 Android 11+ 可控扫码 UI），“扫码后无需手填端口”只有单元测试覆盖。
- 设备换端口时序、多网卡、IPv6-only 链路未实测。
- 复测方式：关闭并重建应用后重新扫码，`settings.json` 中的旧端口应被改写成 server 当前端口，或在新直连配对成功后删除；设备列表应只剩一个端点。
