# 宿主组合根与装配收敛（DI 显式工厂注册 / 装配单一事实源 / 参数对象）

面向 NativeAOT 的组合根整理：三个批次全部落到显式工厂注册，不使用反射式 DI、程序集扫描或 `ActivatorUtilities`；注释保持中英双语 XML，未新增 `NoWarn`。

## 批次 1 — 组合根与静态门面

| 项 | 落地 |
| --- | --- |
| 共享 HttpClient | 新增 `UotanStudio/Services/Network/SharedHttpClient.cs`：进程级客户端 + `Create(timeout)`；`UotanStudio/Services/Scrcpy/ScrcpyServerService.cs`、`UotanStudio/Services/PatchPackages/RootPatchPackageService.cs` 不再各自 `new HttpClient`；`UotanStudio/ViewModels/Shell/MenuViewModel.cs` 的选择器改用 `Create(2h)` |
| MCP 单例 | `UotanStudio/Composition/ServiceRegistration.cs` 注册 `HttpClient`、`ScrcpyServerService`、`RootPatchPackageService`、`McpToolCallLog`、`McpExposureService`、`McpClientConnectionService`；`UotanStudio/App.axaml.cs` 改为 `ServiceHub.GetRequired<...>()` |
| 静态门面去单例 | 5 个 VM 家族约 280 处 `LanguageService.Instance` / `LogService.Instance` 改为 `_localizer` / `_log`：`FlashViewModel`（含全部 partial）、`MenuViewModel`、`SchemeOperatorViewModel`、`PropertiesViewModel`、`DeviceViewModel`（含 5 个 partial）。注入点统一为 `ILocalizer? localizer = null, IUnifiedLog? log = null`，缺省回退共享服务（沿用仓库既有「容器优先、测试回退」约定），容器注册传 `ILocalizer`/`IUnifiedLog` |
| 依赖下推 | `UotanStudio/Services/Mcp/McpExposureService.cs` 新增带依赖工厂的构造函数（设备网关 / 交付工具 / 签名密钥），`ApplyAsync` 不再现场 `new` 三个依赖 |

## 批次 2 — 装配单一事实源

- `UotanStudio/Composition/ShellComposition.cs` 新增 `CreateMenu` / `CreateNodes` / `CreateSettings` / `CreateWorkspace`；容器注册与两条装配路径都调用这四处唯一定义，删除重复构造逻辑。
- 7 个 View code-behind（AvbTool、Checksum、ApkSigning、KeyManager、SchemeEditor、UsbTree、VisualPluginManager）改为 `ServiceHub.TryGet<T>() ?? new T()`，对应 VM 以 `AddTransient` 注册。

## 批次 3 — 契约化与参数对象

- `UotanStudio.Delivery/Build/DeliveryService.cs` 主构造函数新增 `IDeliveryTools? tools`，内部测试构造函数转发，构建不再每次 `new DeliveryToolService`。
- 新增 `UotanStudio.Mcp/McpServerComposition.cs` 参数对象；`UotanStudio.Mcp/McpServerHost.cs` 只保留一个真正的构造函数，原 4 个重载全部转发（公共 API 与测试零改动）。
- `UotanStudio.Comm/Devices/Services/Sessions/DefaultDeviceSessionFactories.cs`：HDC / Fastboot 会话工厂复用同一协议工厂实例，Comm 不引入容器。

## 实测门禁（改动完成后同一时段）

- `dotnet build UotanStudio.slnx -c Debug`：0 错误 0 警告。
- `dotnet format`（style / whitespace `--verify-no-changes`）：改动文件无 IDE/IMPORTS 报错；whitespace 仅 4 个未触碰文件的既有 `FINALNEWLINE`。
- 定向测试：`ServiceRegistrationTests` 3/3、`FlashViewModelCommandTests` 2/2、`McpToolCatalogTests` 6/6、`McpHttpExposureTests` 4/4、`PropertiesViewModelFileSizeTests` 7/7。
- `dotnet publish UotanStudio.Desktop -c Release -r win-x64 --self-contained`：EXIT=0，产出约 119 MB 原生 exe；`UotanStudio.*` 程序集无 IL/AOT 警告，只剩第三方包 IL2104/IL3053（Dock.Avalonia、Ursa、LTRData.Extensions、YamlDotNet、Common.Logging）。
- 门禁注意事项：Release 发布后必须按仓库文档重新 `dotnet restore UotanStudio.slnx -p:Configuration=Debug`，否则 `AttachDeveloperTools`/`AttachDockDebugOverlay` 会以 CS1061 失败（根 `AGENTS.md` 已记录，本次复现并按其修复）。验证期间工作区另有并行会话的未跟踪文件（`Views/Editors/RockchipConfigEditorView.axaml` 上 `ViewModels`/`Views` 类型混淆导致 AVLN2000）会让 XAML 编译失败，属他人文件，未改动。

## 明确未做（含理由）

- 未引入 `IServiceScope` 生命周期：容器化 Settings/Workspace 的释放归属会改变关闭时自动保存落盘语义，风险高于收益。
- `McpHttpServerHost` 的 `loggerFactory` 仍为 `null`：未注册日志抽象，直接传会让 MCP 依赖宿主日志设施。
- Mirroring 会话分派、Firmware 编解码静态入口按评估结论保持不动。
