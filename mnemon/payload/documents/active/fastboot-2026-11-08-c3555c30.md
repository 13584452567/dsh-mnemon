# Fastboot 分块刷写进度日志去重：真机验证（2026-11-08）

真机 sm6150（USB 序列号 `6b24c48f`）上的分块刷写端到端验证记录，用于支撑 `PartitionStatusLog` 页面日志判定逻辑与同步进度上报的实现结论。

关联文档：`b1898c91-0104-446e-9ebf-b27f6dcb61c6`（同一台设备 6b24c48f 的 ADB/HDC 远端连接修复与真机矩阵）。

## 问题背景

分块刷写阶段，原始进度回调按上传进度频繁重复上报（`Uploading chunk 1 of 5…` 同一条文案连续数十次），页面日志若不判定去重会把同一块刷屏；同时重切镜像阶段缺少一行提示，会让上一条“打开 fastboot 会话”文案一直停留。

## 修复形态

- `UotanStudio/Services/Flash/PartitionStatusLog.cs`：页面日志判定器，按“分区 + 阶段文案”去重，保证每个分块只落一行。
- `UotanStudio/Services/Flash/SynchronousFlashProgress.cs`：同步进度上报，避免滞后回调在块内堆积。
- 接入点：`UotanStudio/Services/Flash/FlashService.cs`（`FlashImageChunked` 路径）、`UotanStudio/ViewModels/Flash/FlashViewModel.Operations.cs`。
- 回归用例：`UotanStudio.Tests/Flash/FlashChunkedProgressTests.cs`、`UotanStudio.Tests/Flash/PartitionStatusLogTests.cs`。

## 真机验证过程（Windows x64，设备 6b24c48f / product=sm6150）

1. 设备原处于 ADB 模式，执行 `adb reboot bootloader` 后重新枚举为 `USB\\VID_18D1&PID_D00D`（Android Bootloader Interface），fastboot 端点可用。
2. 只读探测设备变量，结果为判断“是否真的进入分块路径”的依据：

   | 变量 | 值 |
   | --- | --- |
   | `max-download-size` | `805306368`（768 MB） |
   | `partition-size:system_a` / `system_b` | `0xC0000000`（3 GB） |
   | `slot-count` / `current-slot` | `2` / `a` |
   | `product` | `sm6150` |
   | `is-userspace`、`version` | 不支持，返回 `GetVar Variable Not found` |

3. 用 `FlashService.FlashImageChunked` 把 `D:\\Firmware\\SM7150\\system_a.img`（3 221 225 472 字节）真实写入 `system_a`：镜像远大于 768 MB 上限，实际切成 **5 块**，耗时 **66.9 秒**，全部 `flash:` 返回 OKAY。
4. 血压计式的读数：此次真实刷写共产生 **511 条**原始进度上报，经 `PartitionStatusLog` 判定后输出 **7 行**：

   ```
   system_a: Converting the image to sparse…
   system_a: Re-cutting the image into download-sized chunks…
   system_a: Uploading chunk 1 of 5…
   ...
   system_a: Uploading chunk 5 of 5…
   ```

   中文界面为“正在转换为稀疏镜像… / 正在重新切割镜像… / 正在上传第 N/5 块…”。
5. 刷写后执行 `fastboot reboot`，设备回到 Android 并由 `adb devices` 正常上线，说明该次实写未损坏设备。

- 临时探针用例与临时日志在验证后全部删除，`git status` 只剩正式改动。

## 环境与操作前提

- 本机 `adb`/`fastboot` 不在 PATH 上，可用的是 `E:\\UotanToolboxNT\\UotanToolbox\\bin\\Release\\net10.0\\Bin\\platform-tools` 下的副本。
- 重新构建测试项目前若上一次测试宿主仍存活，会以 `MSB3027/MSB3021`（exe 被锁）失败；先结束 `UotanStudio.Tests` 进程再构建。
- Debug 还原/构建必须显式 `-c Debug` / `-p:Configuration=Debug`，否则 `App.axaml.cs` 的 `AttachDeveloperTools`、`AttachDockDebugOverlay` 会 `CS1061`（该约束已写在仓库 `AGENTS.md`）。
- 真机验证通过带环境变量开关的正式用例写法启用，探针临时文件只放 `%TEMP%` 并在结束后清理。

## 未验证边界

- 真机只覆盖 `system_a` 的分块写入；`system_b`、写入后内容校验（回读比对）与 `boot_a` 等小分区在真机 UI 上的完整流程均未在本轮重复执行。
- `UotanStudio.Desktop` 的 Release NativeAOT 发布未在本轮运行。
