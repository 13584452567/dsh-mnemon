# 烧录面板：`Field<T>` 与 XAML 控件名对齐（已清零）

## 1. 不变量

`FlashViewModel` 分部中的每一次 `Field<T>("Name")` 都必须在 `UotanStudio/Views/Shell/FlashView.axaml` 中存在同名 `Name=` 控件；XAML 里没有的控件没有对象可寻址，任何读写或 `IsEnabled` 赋值都对应一个界面上不存在的入口。

复核方式（可重复执行）：分别抽取 .cs 里 `Field<...>("...")` 的名称集合与 `.axaml` 里 `Name="..."` 的集合，求差集。清理前差集为 **43 项**，现在为 **0**。

清理后仍出现旧名称的只剩两类，都不属于控件引用：

- 本地化资源键（RPMB / NAND / UFS / preloader 等），供 Comm 与工作流节点继续使用；
- 设备层服务与协议枚举。

## 2. 因控件缺失而删除的通路

### 2.1 校验开关 `VerifyAfterFlashBox`

全仓不存在该控件，因此删掉 4 处读取与 `RunSelectedAsync` 里的 `verifyRequested`/`verify` 变量：

- EDL 三处（bundle、分区编程、GPT 编程）与 MTK 一处调用统一 `verify: false`；
- RKDL 调用去掉该参数；
- 资源键 `Flash_VerifyUnsupported` 提示不再可达。

即：从烧录面板出发**当前无法请求刷写后校验**，校验能力仍在设备层（如 `ProgramRawPartitionFromFileAsync(verify: …)`）。

### 2.2 EDL 串口路径

`RunEdlBundleAsync` 去掉 `useSerialPort`/`serialPort` 参数与"复核串口仍在"、设备名二选一的分支，确认与刷写统一走单一 USB 路径；`EdlSerialPortBox`/`EdlSerialBaudBox`/`EdlSerialFlashButton`/`FlashEdlBundleButton` 引用全部清零。设备层 `FlashEdlSerialAsync` 保留。

### 2.3 MTK 串口与附加代理

- 删掉 `MtkPortBox`、`MtkAttachAgentBox` 的读取，`attach` 固定 `false`；
- 串口场景改为接触设备前的本地拒绝，新增资源键 `Flash_MtkSerialUnsupported`（"此面板没有串口选择控件，联发科设备需要通过 USB 连接"），中英 resx 与 `UotanStudio/Locale/LocaleKeySets.cs` 同步；
- 删掉三处仅 `attach` 可达的分支。

结论：面板上 EDL 与 MTK 都只剩 USB 通路；Comm 侧的串口、UFS、NAND、preloader、RPMB 能力**未被删除**，只是不再从烧录面板触达（工作流节点仍在用）。

## 4. 教训：按行区间删除会连带裁掉相邻活成员

按行区间批量删除时有三处相邻成员被误裁，都是 XAML 与 code-behind 仍在调用的活代码：

- `OnChooseMtkDaClick`
- `OnEdlChooseProgrammerClick`
- `RunMtkSecurityOperationAsync`（XML 属性查询 `OnMtkXmlPropertyQueryClick` 仍依赖）

恢复方式：从 HEAD 原样取回这三个成员。核对手段值得保留——**生成"HEAD 成员清单 vs 当前成员清单"的差集**，确认差异只剩本次有意删除的成员；仅靠编译通过不足（误裁后编译一度报 `CS0103: verifyRequested / verify 不存在`，而这类错误指向的是删除点的下一跳而非删除本身）。
