# RKDevTool 下载列表 cfg：头部/行布局核验与导入行为（2026-11 复核）

对照 RKDevTool v2.96 随附的真实 `config.cfg`（10399 字节 / **17 行**）、`rock-5b-emmc.cfg`、`rock-5b-spinor.cfg` 逐字节核验了 `RockchipConfigFile` 的解析与序列化，并据此修正了头部写入、字段编码与配置行导入行为。

> 尾块（`+4` 存储位掩码、`+8` 行地址）的偏移推导见既有文档 [RKDevTool cfg 尾块布局复核](669d2f16-a028-4b5a-93d9-b65c804ac507)。本文补齐头部、变长约束、操作行分类与导入行发布策略，并更正其中「`+0` 镜像行恒为 `0x53000000`」的说法。

## 1. 证据来源与为什么不能用 rkdeveloptool 对照

`reference/rkdeveloptool` **没有** cfg 解析实现：它只按命令行接收镜像、parameter 与 LBA，cfg 是 RKDevTool 的私有下载列表。因此字节级依据只能取厂商随附文件，对照价值仅限于协议语义（存储 ID/位掩码、loader、parameter 表、LBA 寻址）。

采样：`rock-5b-spinor.cfg`(2022-10-20 19:01)、`rock-5b-emmc.cfg`(2022-10-20 16:20)、`config.cfg`(2026-10-29 10:02:56，17 行)。此前把 `config.cfg` 当成 2 行副本的记录是错的。

## 2. 头部与行布局（已确立）

29 字节头部：

| 偏移 | 内容 |
| --- | --- |
| 0..3 | `"CFG\0"` |
| 4 | u16 `29`（头部长度） |
| 6 | 8×u16 本地时间：年、月、星期、日、时、分、秒、毫秒（与文件 mtime 一致） |
| 22 | **u8 行数** |
| 23 | u32 `29`（重复长度） |
| 27 | u16 `0x0262`（记录标记，与每行开头相同） |

行：固定 610 字节 = `u16 0x0262` + 80B UTF-16 名称（39 字符 + NUL）+ 512B UTF-16 路径（255 + NUL）+ 16B 尾块（`+0` 未确立字、`+4` 存储位掩码、`+8` u32 地址、`+12` u32 标志）。行数由文件长度决定，头部行数字节在解析时只透传——所以旧版导出的文件仍可读。

地址是**扇区/LBA**：17 行样本为 `0x2000/0x4000/0x6000/0x7000/0xA000…0x1308000`，符合 RK 默认 parameter 布局；早期按 `u64@+0` 读取是错误的。

## 3. 修正的缺陷

1. **头部写不完整（导出缺陷）**：`CreateHeader`/`Serialize` 原先只写魔数与 u16 长度，行数字节恒为 0，RKDevTool 读到的导出文件等于声明 0 行。现在写行数、重复长度与记录标记；新增 `HeaderRowCountOffset`(22)、`HeaderLengthWordOffset`(23)、`HeaderRecordMarkerOffset`(27)。
2. **超长名称/路径被静默截断**：`EncodeField` 会截断到字段容量，256 字符路径会变成另一个不存在路径。现在超限抛 `ArgumentException`（名称 >39、路径 >255），行数 >255（u8 字段）也拒绝。
3. **空路径行被丢弃**：17 行样本中 `misc`/`bootctrl`/`eng_system`/`eng_chipset` 无文件（`+12` = 0，即 RKDevTool 未勾选行）。现在这类行也发布为条目，导入后是 17 行而非 13 行。
4. **`Parameter` 行被当成分区镜像**：样本首行 `Parameter → parameter.txt` 是分区表；原实现勾选后会把 .txt 写进名为 `Parameter` 的分区。新增 `ClassifyOperation` 识别为 `parameter` 命令行，不可勾选、不参与刷写。
5. **`NormalizeStorage` 缺失**导致一次 `CS0103`；抽成独立函数后解析与序列化共用同一归一化，字节级往返恢复通过。

## 4. 配置行导入与可选性策略

`FlashViewModel.Rockchip.cs` 的 `ApplyRkConfigRows` 用配置整体替换分区列表（重复导入不叠加），行为分档：

| 行类型 | 可勾选 | 默认勾选 | 状态列 |
| --- | --- | --- | --- |
| 有文件的分区行 | 是 | 否 | 空 |
| 空路径行（无文件） | **是** | 否 | 空 |
| 路径已写但文件不存在 | 否 | 否 | `Flash_FileMissing`（「文件不存在。」） |
| `Loader` / `Parameter` 行 | 否 | 否 | 空 |

关键条件：`CanSelect = operation == Flash && (exists || entry.Path.Length == 0)`；空路径行可勾选是用户明确要求，默认不勾选沿用 `FlashPartitionEntry.IsSelected = false`。勾选空路径行后会在写入前检查处报「文件不存在。」并中断；也可先用行内「选择文件」挂镜像。

界面文案：烧录页状态文本由「镜像文件不存在」改为「文件不存在」；Loader 行不再有专属说明（`Flash_RkLoaderRow` 已从两份 resx 与 `LocaleKeySets` 移除，`Flash_RkLoaderDeclared`/`Flash_RkLoaderMissing` 日志文案保留），文件存在时为空、缺失时显示 `Flash_FileMissing`。`loader` 命令值、不可勾选、不参与刷写的行为不变。

## 5. 仍未覆盖 / 未验证

- **每行地址未被刷写使用**：刷写按分区名查 parameter 表取 LBA，未实现 RKDevTool 的「强制按地址写」（rkdeveloptool `wl <lba> <file>`）；配置地址与设备分区表不一致时仍按分区表写。
- **cfg 的 Parameter 行路径未接入刷写**：`FlashService.FlashRkdlAsync` 仍在镜像目录按 `parameter`/`parameter.txt` 约定查找，配置指向别处会失败（识别已做、路径打通未做）。
- **尾块 `+0` 与 `+12` 语义未确立**：17 行样本 `+0` 全为 0，两行样本的 `Image` 行是 `0x53000000`；`+12` 观测为「有文件=1、无文件=0」，是否等价勾选状态未证实（`Selected` 已读出，界面未使用）。两者均原样透传。
- **存储位掩码只部分证实**：样本仅出现 0、2、512；协议 ID 为 `1=EMMC, 2=SD, 9=SPINOR`（`reference/rkdevtool` 的 `storage_from_ui_no` 证明 UI 序号 ≠ 协议序号）。NAND/SPINAND/RAM/SATA/PCIE/UFS 的位序未证实，`DescribeStorage` 只命名已知三种、其余显示十六进制。
- 保存时未刷新头部时间戳（按原 header 透传）。
- GUI 未人工点验；真机与 RKDevTool 打开本仓库导出文件的互操作未实测（建议手动导出一次在 RKDevTool 中确认行数与勾选列）。
