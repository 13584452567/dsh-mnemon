# 配对后设备重启 TLS 服务导致死会话复用（Windows x64 / .NET 10）

上一轮把“扫码后端口解析”继续加固后仍有真机复测失败。本轮先用抓包把“端口对不对”这件事定死，再把根因定位到**失效 TLS 连接被共享会话池反复复用**。

相关背景文档：`08377954-fdfb-4623-b6d7-11a2afbe0515`（配对后持续重新浏览、最近广播优先与 `host:connect` 复核）、`a1040553-a8fc-487d-948f-157183fd1cfa`（配对后自动发现端口 + 共享 ADB 会话与 `AdbConnection` 写失败失效）、`5cfde066-d749-4e66-8f39-c819d853361e`（server 实例名识别与直连端口重试）、`65b080df-c163-4577-8543-ecbb049d88ac`（`host:pair` 结果帧与进程内 SPAKE2 回退）。

## 决定性证据：端口本身是对的

在本机对 mDNS 抓取 12 分钟（`2026-10-26 00:50:16` → `01:02:18 +08:00`），设备持续广播：

```
00:57:16  adb-6a082bda-lZgxIP._adb-tls-connect._tcp.local  192.168.1.144:45105
00:57:20  adb-6a082bda-lZgxIP._adb-tls-connect._tcp.local  192.168.1.144:45105
00:57:25  adb-6a082bda-lZgxIP._adb-tls-connect._tcp.local  192.168.1.144:45105
00:57:47  adb-6a082bda-lZgxIP._adb-tls-connect._tcp.local  192.168.1.144:45105
```

app 使用的 `192.168.1.144:45105` 与广播完全一致，因此“无 server 直连端口解析错”的旧假设被排除：**配对完成后设备侧重启了 TLS 服务（端口不变），把已建立的连接断开**。

## 根因链

1. `AdbTlsTransport.IsConnected` 只看 `_stream != null`，托管 TLS 已 `closed/failed` 时仍报告“已连接”。
2. 共享会话池只在 `!IsConnected` 时淘汰，于是**死会话长期留在池里**，logcat 进程名刷新、属性查询、投屏继续复用它。
3. 现象：`Cannot write application data on closed/failed TLS connection`、`ObjectDisposedException: System.Net.Sockets.Socket`，设备管理器拿不到属性，日志与投屏不可用。

## 修复

- **链路真实状态**（`UotanStudio.Comm/Transports/Tcp/AdbTlsTransport.cs`）：新增故障标记；托管 TLS 的 `IsClosed`/`IsFailed`，以及读写抛出的 `IOException`/`SocketException`/`ObjectDisposedException` 都把传输标记为断开，重连成功后清除；`AdbConnection.IsConnected` 同时要求传输仍可用。
- **死会话立即淘汰**（`UotanStudio/Services/Devices/DeviceMonitorService.SharedAdb.cs`、`...Logs.cs`）：`RunSharedAdbSession(Async)` 与 logcat 捕获收到任何“连接丢失”类失败时**无条件**把共享会话移出池，不再以 `IsConnected` 为真为由保留；下次借用重新打开并按 IP 重新解析端口。
- **端点改写后刷新界面**（`DeviceMonitorService.Remote.cs`、`...Sessions.cs`、`...Transactions.cs`）：`OpenDirectNetworkAdbLease` 重新解析端口、以及扫描期对齐 server 目标这两条路径都会触发设备列表刷新，并丢弃旧键的池内会话，避免 UI 继续持有旧端点。
- **直连端口解析加固**（`UotanStudio.Comm/Protocols/Adb/Pairing/AdbQrPairingService.cs`；mDNS 实现保持不变）：每轮先实时浏览再探测，期限 20s → 30s；8 秒宽限后把同一主机上其余广播端口也试一遍（覆盖双栈/主机名不一致）；失败消息列出“观察到的实例 + 尝试过的端口”。
- **有 server 链路顺序不变**：`host:pair` 成功 → 重读 `host:mdns:services` → `host:connect:` 连接行（与上游命令行两步对齐）。

## 仍未验证的边界

- 本机无 Android 11+ 无线调试环境，“配对后 adbd 再重启一次 TLS 服务”的重连时序只能真机验证；`AdbRemoteProtocolTests` 只覆盖 STLS 常量、明文收到 `A_STLS` 快速失败与分部读取。
- 换端口时序、多网卡与 IPv6-only 链路仍未实测；真实扫码 UI 与扫码后免手填端口未在真机确认。
- 退化时先关闭运行中的 app 再重建（否则 `bin/Debug` 被锁）；复测失败应收集带 `observed [...]` 与 `tried ports [...]` 的 `DevicePairing - QR pairing failed: ...`，以及 `AdbLog`/`DeviceManager` 行。
