# 投屏四项修复归因与实测（2026-10-25）

一轮修复同时收尾四个问题：HDC 冷启动卡在“正在连接”、关闭投屏约 1 s 卡顿、按“多久没帧”判定断联的误报、两台真机并行投屏验证。逐字实测记录在仓库 `VERIFICATION.md`（自 L251 起）。

既有相邻文档不要混淆：端点占用与遗留会话回收见 `6f754ead-5fb1-4813-8e9c-cdc70dcbc7cb`、`13d2945f-9a23-4bc7-8aa9-ac82e702b5c8`；解码线程被单帧异常杀死 / USB 清单陈旧 / HDC server 客户端生命周期见 `64a77aaf-9665-44d1-8b37-0bfd4194e9e2`。本文只记录本轮新增的真实挂死点与两处“时长即故障”的误判语义。

## 1. HDC 冷启动卡在“正在连接”：gRPC 请求缺单次尝试上限

现象：冷启动 HDC 投屏（`--open-screen-mirror 5XM0225C18001159`）不出画，界面无限停在“正在连接”；进程与窗口都响应，UI Automation 树正常（`targetResponsive: true`），说明不是 UI 线程死锁而是某次 RPC 永久等待。

根因：**gRPC 视频请求没有单次尝试超时**。隧道处于半开状态时 `SendAsync` 不会返回也不报错，上层的重试循环永远拿不到失败结果，于是“正在连接”再无后续状态迁移。控制器/守护进程的存活是有界的，唯一无界的就是这一次 RPC 本身。

修复：给每次尝试加上限并让重试真正生效——视频请求 4 s、关键帧请求 3 s；超时按“本次尝试失败”处理，交回已有重试循环，而不是终结会话。

这是“重试机制写好了但永不触发”的典型形态：判断稳定性时不能只看重试次数配置，必须确认**每次尝试本身有超时**，否则半开连接会把重试循环整体钉死。诊断抓手是响应式窗口 + 停在连接中的界面 + 无 I/O 进展，而非崩溃日志。

同一轮并入的启动期稳定性改造（与本根因互补，不是重复）：失败分 A（未就绪可重试）/B（能力不足不可重试）/C（已启动但视频失败）三类；UI Test 探测与推送落盘重试；控制守护进程 10 s；扩展 6 s 并做存活复检；控制 socket 15 s 重试；按目标串行化的启动门。

实测：冷启动由“卡在正在连接”变为正常出画，视频区均值 39.29、max 255。

## 2. 关闭投屏约 1 s 卡顿：UI 线程同步 Join 泵 + 同步归还租约

根因：关闭路径在 UI 线程上依次 `Join` 解码/音频/控制泵；解码泵可能正卡在一次 `ReadFrame(1000)` 上（画面静止时必然等满 1 s）；随后仍在 UI 线程同步释放 ADB 租约。三处叠加使 UI 冻结约 1 s。

修复：UI 线程只做状态复位与帧释放；泵停止、client 释放、租约归还移到专用后台任务；新增会话代际，丢弃上一会话迟到的帧，避免关闭后又被旧帧拉回运行态。

实测方法（可复用）：`SendMessageTimeout(WM_NULL)` 探针，约 700 次 / 25 s 采样。静态画面下关闭瞬间 UI 最大延迟 9.4 ms，p95 0.5 ms，无一次超过 200 ms；关闭后设备日志继续刷新，重新投屏正常出画。

## 3. 取消“多久没帧就断联”的判定

按用户要求删除全部基于时长的断联判定：5 s 无解码帧就重建、3 s 等不到关键帧就报 `The server produced no key frame after the decoder rebuild`。等待关键帧改为每 2 s 重发 `ResetVideo`；只有真实解码错误才重建一次。

理由：安全视图（锁屏/熄屏/密码页）本就不产生可捕获帧，时长阈值把正常状态误判成故障并触发解码器重建，反而造成画面停住。

实测：锁屏/熄屏期间不再出现 `No decoded frame … 5000 ms` 或 `Decode failed`，会话保持“投屏中”。

设计取舍：把“是否存活”交给真实解码错误与显式的 `ResetVideo` 重发，而不是把沉默当作证据；代价是真正的静默挂起需要更长时间才被发现，这是有意选择。

- 设备管理器同时识别两台，详情（品牌/型号/系统版本/SDK/ABI）完整。
- 同时开 HDC 与 ADB 两个投屏标签并来回切换：ADB 画面保持（视频区均值 72.70 → 72.61，max 255，569232 个采样像素中仅 852 个变化）；注入“最近任务”后视频区变化 127776 个采样像素，说明画面与控制通道同时存活。

## 未验证边界

- HDC 采集库与该机型 HarmonyOS 的 protobuf/gRPC ABI 兼容性属设备侧边界：不匹配时按 B 类快速失败并引用采集日志，软件层无法修复。
- 冷启动本次通过，但同一设备此前出现过一次 C 类视频失败；未做 20 次以上重复统计，长期稳定性不能写成已验证。
- 密码页安全视图只验证了“不误判断联”，解锁后是否自动恢复出画未验证；双设备同时出画未验证（HDC 一路受上述能力边界限制）。
