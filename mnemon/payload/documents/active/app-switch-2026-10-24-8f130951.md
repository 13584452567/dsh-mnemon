# 投屏呈现恢复状态机与 APP_SWITCH 和弦控制

相关设计：ohscrcpy 投屏重写（UI Test 扩展 + h2c gRPC 视频 + UI Test JSON/uinput 控制），id `fe4bd5e7-924b-45ec-aa91-975d63f3b737`。本文只覆盖该重写之上的呈现恢复、按键映射与 HDC 启动选项，不重复基础控制通路与会话所有权。

## GPU 合成表面恢复

- 新增纯状态机 `ScreenMirrorCompositionRecovery`（`UotanStudio/Views/Editors/ScreenMirrorGpuPresenter.cs`）：用代际令牌使在途探测/呈现失效；离开可视树后 **250ms 去抖**再真正分离，快速回挂（停靠浮动、拖拽）直接复用表面；瞬态失败可在下次挂载恢复，只有合成器能力缺失才视为终止失败。
- 分离时按代际清理旧 interop 的 imports；重建 surface 后**不复用旧 image**，避免一次失败把呈现永久锁在禁用状态（原实现的 `DisableComposition` 永久化问题）。
- 重新挂载成功后触发 `CompositionRestored`，`ScreenMirrorViewModel` 订阅后发送 `ScrcpyControlMessageWriter.ResetVideo()`（由 `ScrcpyToOhscrcpyControlAdapter` 映射为请求关键帧），使浮动/拖拽后的首帧不必等下一个自然关键帧。
- `ScreenMirrorVideoControl` 在 `OnDetachedFromVisualTree` 调 `ScheduleDetachCompositionVisual`，DataContext 变化时对旧模型 `DetachCompositionVisual` 立即分离；`ScreenMirrorView.axaml.cs` 重新挂载时 `InvalidateVisual()` 复用位图回退。

## 位图回退门控

- 合成帧覆盖视频区域前始终绘制最新位图帧（重建 surface 首帧前保持透明）。
- 位图帧删除条件由 `GpuPresenter.IsAvailable` 改为 `CanPresentFallback`（`_available && !_failed && !_closed`），GPU 回退失败时不再误删位图，避免黑屏。

## APP_SWITCH 和弦控制

- `ScrcpyToOhscrcpyControlAdapter`：`187 (APP_SWITCH)` 不再走单键映射；按下沿产生一次 `KeyChord(META_LEFT=2076, TAB=2049)`，抬起沿无动作，与 DevEco 插件 `DeviceController.recentApplication()` 同源。
- `OhscrcpyControlChannel.SendKeyChord` 生成 wire 命令 `uinput -K -d 2076 -d 2049 -u 2076 -u 2049`；`OhscrcpyClient` 新增 `KeyChord` 分派；Home/Back/Power/Volume/文本/触摸映射未改动。
- 契约新增 `OhscrcpyControlActionKind.KeyChord`、`SecondaryKeyCode`（其余动作恒为 0）与 `SendKeyChord` 接口方法。
- 测试：`ScrcpyToOhscrcpyControlAdapterTests` 覆盖 187 按下/抬起、未知键、专用键回归；客户端保证只下发一次 chord；新增 `OhscrcpyControlChannelTests` 断言命令字符串。

## HDC 启动选项

- `ScreenMirrorViewModel` 的 HDC 分支不再调用 `OhscrcpyServerService.ResolveOrProvisionAsync`、不再显示“安装 server”，改为由设置快照构建 `OhscrcpyLaunchOptions`：`0 fps` 视为不限并取 60，帧率收敛 1..120，码率收敛 1..50 Mbps，每 2000ms 强制关键帧。ADB 分支仍保留安装提示。

## 验证状态与边界

- 检入点证据仅有各子任务复核与定向用例；统一验证（构建、定向测试、格式门）与 `t4` 尚未完成，真机/浮窗拖拽与 250ms 时序仍需人工复核，不能视为已通过。
- 路由侧（ServerOnly 拒绝直连、直连回退、清理顺序）由既有 `fe4bd5e7` 文档描述，本次仅复核未改契约。
