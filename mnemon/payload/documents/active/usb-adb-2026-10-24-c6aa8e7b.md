# 直连 USB ADB 端点“释放中占位”卡死：修正归因与修复（2026-10-24 后续）

对既有归因（`13d2945f-9a23-4bc7-8aa9-ac82e702b5c8`、`cf882e65-ccd3-495b-88c1-257498f9f5b5`：详情补全/日志抓取占用端点为根因）的**修正与补充**：真机日志证明占用者在报“已归还”之后端点仍不可打开，根因在 Comm 租约表的占位条目未被回收；既有文档中“补全持有数秒导致投屏撞车”只是表象之一。

## 观测证据（真机设备日志时序）

```text
[Debug] usb - opened \\?\usb#vid_05c6&pid_90db&mi_05#...: bound alt setting 00 (FF/42/01) ...
[Debug] lease - released reservation for usb/Native native|Native|05C6|90DB|FF|42|01|6b24c48f|...
（约 2 s 后）
错误详情(原始信息): Endpoint is already leased.
```

即：前一个租约已打印 “released reservation”，随后投屏启动仍被拒绝。GUI 侧同一条错误在设备日志窗口稳定复现（UIA/OCR 命中 “Endpoint is already leased.”），设备详情、日志抓取、投屏同时失败。

## 根因（Comm 层）

- `UotanStudio.Comm/Devices/Services/DeviceController.cs` 用两张表：`_openLeases`（活动租约）与 `_leased`（端点独占标记）。
- 强制分离路径（设备移除、adb server 消失、投屏急停）先把租约从 `_openLeases` 摘除，但 `_leased` 中的条目作为**“释放中占位”**一直保留到该租约的异步清理完成（见 `_leased.Remove(id)` 处的注释）。
- 若清理永不完成（设备已不在、传输 dispose 卡住），该端点**永久不可再打开**，而 `DescribeReservations(address)` 只读 `_openLeases`，对外表现为“没人占用”。
- 宿主据此的“摘除 → 等待归还”循环既等不到人，也判断错对象，最终把原始 `Endpoint is already leased.` 直接抛给用户。

## 修复

1. **占位超过 1 s 视为清理卡死并回收**：`OpenTransportAsync` / `AdoptSession` 取得占用时回收过期占位，并写一条含卡住时长的错误日志。存活租约绝不被抢占。
2. **`DescribeReservations` 说真话**：把占位条目报成 `source/transport releasing placeholder`，占用者清单不再漏报。
3. **宿主重试一次**：`DeviceMonitorService.ControlledSessions.cs` 的 `OpenAdbLease` 遇占用先记录占用者 → 摘除（`ForceDetachReservations`）→ 重试一次，仍失败才抛带占用者清单的 `IOException`。`ReleaseStubbornEndpointHolders` 保留 5 s 上限等待（`StubbornReleaseWaitTimeout`），因端点单持有者，超时即判定卡住。
4. **设备信息刷新不再卡界面线程**：`EnrichMtkInfoAsync` / `EnrichEdlInfoAsync` 原先在调用线程直接等待同步阻塞的 USB/协议调用，5 s 预算原样落在 UI 线程；改为 `Task.Run` 后台执行（入口 `UotanStudio/ViewModels/Devices/DeviceViewModel.Details.cs` 的 `BeginBackgroundEndpointWork`）。
5. **`DeviceMonitorService.Scan()` 锁等待上限压到 250 ms**：超时返回上一份快照并记录耗时（≥400 ms 打印 “Full scan took … ms”），刷新点击不再被整段枚举拖住。
6. **设备日志捕获失败退避**：同一设备捕获失败后不再被任意一次列表刷新立即重启（原先每 ~11 s 重复“清空 10 s 超时 + 一批取消”），改为 5 s 退避。

## 明确未修

投屏窗口被遮挡/最小化后不恢复、状态仍显示“投屏中”。`ScreenMirrorCompositionRecovery` 只覆盖“可视对象分离 / 重新挂载”（停靠浮动、拖拽），没有任何窗口遮挡或前台状态驱动的会话暂停与状态复位钩子。补齐需要真机复现，本轮无设备，未实现。

## 验证与边界

- 本机无连接设备，只能做同场景（无设备）GUI 实测：修复前构建稳定出现 `Endpoint is already leased.`；修复后该错误消失，设备日志正常渲染，UIA 查询 0.39–0.74 s 返回，交互（下拉菜单、Esc）约 0.2 s 无卡顿。
- `dotnet build UotanStudio.slnx --no-restore -c Debug` 0 错误（需先结束正在运行的 `UotanStudio.Desktop`，否则 MSB3027/MSB3021 拷 DLL 失败）；定向测试 Devices 247/247、Protocols 41/41、Media 204/204（1 跳过）；whitespace 与 style 零报告。
- 未验证：投屏实际拉流、详情补全的真机路径、1 s 占位回收在真机上的表现；结论部分来自日志推断与假件，需真机复跑确认。
- 结论已写入 `VERIFICATION.md`（根因段落）。
