QRD7150 EDL root cause (verified): the 9008 device's BusReportedDeviceDesc is "QUSB_BULK_CID:040F_SN:9806169E" (Qualcomm BULK endpoints), but on this host it is bound by oem36.inf / service qcwdfserial into Class=Ports and exposed as COM12. UotanStudio's EdlSerialPortFallback then talks to it via System.IO.Ports.SerialPort (CDC-ACM). That path can move bytes but does NOT reach the Sahara command endpoint, which is why the target replies to any input with a constant 16-byte packet and never parses HELLO_RESPONSE. Other EDL tools succeed on this same device because they open the raw BULK endpoints directly. Two 9008 instances exist (40000030 -> COM12 Status OK; 20000030 -> COM9 Status Unknown). Fix is to rebind the 9008 interface to WinUSB (libwdi's winusb_generic_device.inf is already installed, USBDevice class) or libusb-win32/libusbK so the native USB backend claims the interface instead of the serial fallback.

UotanStudio.Compress 门面异常语义陷阱：CompressionService.CreateDecompressionStream 返回的惰性读取器不包装异常。CompressionFormat.Deflate 走 SharpCompress，损坏数据抛 SharpCompress.Compressors.Deflate.ZlibException；CompressionFormat.Gzip 走 BCL GZipStream，抛 System.IO.InvalidDataException。两者都不是 CompressionException（该类型 internal，仅 InternalsVisibleTo 到 Firmware/Tests/Benchmarks，宿主 UotanStudio 无法 catch）。截断输入在两种实现上都静默返回部分输出而不抛异常。调用方 catch 必须按实际格式分别覆盖对应类型，不能想当然用 CompressionException。
